# 動く地図（GPU 描画）

地図画面の「図 / 動く地図」の「動く地図」。Windy と同じ考え方で、格子データを GPU に渡し、
画面の画素ごとの補間・配色と風の粒子の動きを 1 コマごとに描く。拡大（ホイール・ピンチ）・
移動（ドラッグ）・読み取り（マウスを置くと経緯度と値）は部品の中で完結し、Python と
行き来しない。保存・共有用の図（PNG）は「図」のまま残す（図が製品という方針は変えない）。

## しくみ

| 部分 | 置き場所 | 役割 |
|---|---|---|
| 部品（Flet の拡張） | `packages/flet-gpufield/` | Flutter 側（Dart とシェーダー）で描く `GpuField` と、時刻ごとのデータ `GpuFrame` |
| シェーダー | `packages/flet-gpufield/src/flutter/flet_gpufield/shaders/field.frag` | 画素ごとに投影を逆にたどって経緯度を求め、格子を双一次補間（階級は最寄りの格子点）して配色。陸海の地色 |
| データ作り | `src/aiseed_weather/services/gpu_frames.py` | キャッシュ済みの GRIB・配布パックから、時刻ごとの値・風・等値線を作る |
| 画面の部品 | `src/aiseed_weather/components/gpu_map_panel.py` | 地図画面の「動く地図」で画像の代わりに出す。データを今の時刻から近い順に作って渡す |
| 実行環境 | `client/`、`tools/build_client.sh` → `build/linux/` | 部品入りの Flet 実行環境（下記） |

- 時刻ごとのデータは子の `GpuFrame` として 1 つずつ足す。Flet は足された分だけを送るので、
  全時刻を先に送っておき、時刻の切り替えは番号（`step`）を変えるだけ。次の時刻の GPU 用の
  画像も先に作っておく
- 値は 16 bit に詰めて RGBA の RG に入れる（A が欠測）。8 bit を 2 つに分けているので、
  シェーダーは画像の補間を使わず、格子点を 4 つ読んで自分で補間する
- 値・配色・透明度・乾いた所の切り捨て・等値線の間隔は、図と同じ `ChartSpec`
  （`figures/_chart_specs.py`）から取る。単位の換算もその取り出し関数をそのまま使うので、
  同じ時刻なら図と同じ値・同じ色になる
- 風の粒子は 10m（上空の層はその高さ）の風。直近 12 コマの位置を覚え、細い三角形の列に
  して 1 回で描く（`drawVertices`）
- 海岸線・等値線・数値は、表示も時刻も変わらない間は画像にして使い回し、拡大・移動の
  最中だけ直接描く
- 投影: 正距円筒（地域・全球。全球は経度方向につながる）、北極・南極は正距方位
- 層: 海面更正気圧、2m 気温、10m 風速、降水量（前の時刻から）、上空の気温・高度・風速・
  湿度。描けない層は「図に切り替えてください」と出す
- データは取得しない（user-action-fetch）。手元に無い時刻は飛ばす

## ナウキャストの動く地図

ナウキャストのタブの「図 / 動く地図」の「動く地図」。気象庁の高解像度降水ナウキャストの
過去 1 時間（または 3 時間）と 1 時間先までの予測を、5 分ごとのコマにして同じ部品で描く。

| 部分 | 置き場所 | 役割 |
|---|---|---|
| データ作り | `src/aiseed_weather/services/gpu_radar.py` | メルカトルのタイルを緯度経度の格子に描き直す（1 セルに複数の画素が入るときは最も強い階級）。地域ごとの格子、配色、陸海、海岸線 |
| 画面の部品 | `src/aiseed_weather/components/radar_gpu_panel.py` | `GpuField` と凡例。取得はしない |
| 取得・再生 | `src/aiseed_weather/components/radar_view.py` | 最新の観測 → 予測 → 過去の順にコマを取り、届いたものから渡す。再生は 0.5 秒ごとに番号を進めるだけ |

- 値は強さの階級（0 = エコーなし、1〜8 = 気象庁の凡例、9 = 観測範囲外・欠測）。階級の間を
  補間すると観測されていない強さの縁ができるので、`sampling="nearest"` で最寄りの格子点の値を
  そのまま塗る（シェーダーの `uMode.w`）。読み取りは `classes` の名前（「降水強度 10〜20 mm/h」）
- 範囲外・欠測はコマごとに気象庁の GeoJSON（`hrpns_nd`）から塗り、薄い灰色で覆う
  （エコーなしと見分けられるように。図も同じ色）
- 地域（`_japan_map.AREAS`、図と共通）: 全国・北日本・東日本・西日本・南西諸島。どれもズーム 6
  （約 2 km）。気象庁の粗いズームのタイルは細かい画素の最大値なので、ズーム 4（約 8 km）では
  10 mm/h 以上の面積がズーム 10 の 3.0 倍、ズーム 6 では 1.6 倍になった（2026-10-13 に測定）
- 範囲外にしかかからないタイルは取らない（全国のズーム 6 は 36 枚 → 22 枚）
- 気象庁へは毎秒 4 件まで（コマをまたいでも同じ間隔）。全国の 25 コマで約 2 分半、地方は
  1 コマ 4〜9 枚で 25〜60 秒。取ったタイルは保存するので、同じコマはすぐ出る
- 1 コマは 1 格子点 1 バイト（`GpuFrame.scalar8`）。全国は 1206 × 1222 格子で 1.5 MB
  （16 bit の RGBA なら 6 MB）。RGBA にするのは GPU に置く 8 時刻分だけ

## 実行環境（一度だけ作る）

自作の部品は Flet の出来合いの実行環境では表示されない。

```bash
tools/build_client.sh        # build/linux に作る（約 1 分）
flet run                      # プロジェクトのフォルダーで
```

Linux の Flet は、起動したフォルダーの `build/linux` にある実行ファイルを先に使う。アプリ本体は
今までどおり conda の Python で動き、実行環境だけが部品入りになる。部品（Dart・シェーダー）を
変えたら作り直す。実行環境に部品が入っていなければ、4 秒後に作り方を画面に出す。

## 速さ（2026-10-13、debpc: Intel AlderLake-S GT1 内蔵 GPU、Linux）

| 範囲 | fps | 1 コマの組み立て | 描画（raster） |
|---|---|---|---|
| 日本周辺（0.25°、361×281） | 59 | 7.5 ms | 12 ms |
| 全球（0.5°、720×361） | 58〜59 | 7.8 ms | 11 ms |
| 北極（0.5°、720×141） | 57〜58 | 8.2 ms | 11 ms |

粒子 10,000、等値線・数値・海岸線あり。時刻を 0.2 秒ごとに送り続けても日本 58 fps・全球 46〜50 fps。
データ作りは 1 時刻 30〜70 ms（bulk GRIB は eccodes で見出しだけ走査して必要な通報だけを読む。
184 通報の走査 0.13 秒・1 通報 7 ms。cfgrib は 1 回開くだけで 0.2〜1.6 秒）。

試したこと:
- 尾を毎コマ画像に焼いて薄く重ねる（Windy 型）は内蔵 GPU で 16〜20 fps。線（太さ付き）で描くと、
  線を三角形に分ける手間が描画スレッドに乗って 6,000 で 47 fps。三角形にして渡して 12,000 でも 60 fps
- 海岸線・等値線を毎コマ描くと描画が 14〜18 ms。画像にして使い回して 10〜11 ms
- 尾の点を毎コマ投影し直すと組み立てが 10〜12 ms。画面の位置で覚えて 7.5〜8 ms

## 残り

- 等値線の数値札の置き方（太線ごとに 1 つ。図と同じ）
- 極の投影での地色の継ぎ目、全球の経度のつなぎ目の小さな段差
- Web 版（`flet build web`）でも描けるが、1 コマの組み立てが JavaScript で重い
