# flet-gpufield の設計（flet-gpumap への引き渡し）

格子データを GPU で描く Flet の拡張。AIseed Weather の「動く地図」（モデルの予報とナウキャスト）
で使っている。MIT。aiai-tools に移し、名前を `flet-gpumap` にして、地図とグラフを描ける部品に
広げる予定（2026-10-14 に決めた）。この文書は、いまの作りと、広げるときの案をまとめた物。

## できること（0.1.0）

- 等緯度経度の格子を、色で塗る（256 段の配色表、透明度つき）。透ける所には陸海の地色が出る
- 塗り方は 2 つ: 双一次補間（気温・気圧のような連続した量）と、最寄りの格子点（降水強度の階級の
  ような値。補間すると観測されていない値の縁ができる）
- 風の粒子 10,000 個（直近 12 コマの尾）、等値線（細線・太線）と数値の札、海岸線
- 投影: 正距円筒（全球なら経度方向につながる）、北極・南極の正距方位
- 拡大（ホイール・ピンチ）、移動（ドラッグ）、読み取り（マウスを置くと経緯度と値、階級なら名前）
- 時刻ごとのデータを子の `GpuFrame` で先に送り、`step`（番号）を変えるだけで切り替える。
  再生しても描き直しの待ちがない
- 速さ: Intel 内蔵 GPU（AlderLake-S GT1）、Linux で 57〜59 fps（粒子 10,000、等値線と海岸線あり）

## 構成

| 部分 | 場所 | 役割 |
|---|---|---|
| Python の部品 | `src/flet_gpufield/gpufield.py` | `GpuField`（`ft.LayoutControl`）と `GpuFrame`（`ft.BaseControl`）。値は Flet がそのまま送る |
| Dart の部品 | `src/flutter/flet_gpufield/lib/src/gpufield.dart` | `GpuFieldControl`。プロパティを読み、画像と線を用意し、毎コマ描く |
| シェーダー | `src/flutter/flet_gpufield/shaders/field.frag` | 画面の画素ごとに投影を逆にたどって経緯度を求め、格子を読んで配色する |
| 登録 | `lib/src/extension.dart` | `FletExtension.createWidget` で `"GpuField"` を返す |

Dart の中の主な物:

- `_Grid`: 格子（nx, ny, lon0, lat0, dlon, dlat, periodic）と、経緯度 → 格子の位置
- `_Frame`: 1 時刻分。値（16 bit の RGBA か 1 バイト）、風（int16 の u・v）、等値線と札
- `_Proj`: 投影と表示の位置（中心、縮尺）。画面 ↔ 経緯度、拡大・移動、シェーダーの uniform
- `_GpuFieldState`: 時刻ごとのテクスチャ（直近 8 時刻だけ GPU に置く）、粒子、線の画像の使い回し、
  読み取り、速さの報告

## データの形

| プロパティ | 形 |
|---|---|
| `GpuFrame.scalar` | 格子点ごとに RGBA 4 バイト。RG が `vmin`〜`vmax` を 0〜65535 に詰めた値（R が上位）、A が 255 なら値あり・0 なら欠測 |
| `GpuFrame.scalar8` | `scalar` の代わりに 1 格子点 1 バイト（0〜255 が `vmin`〜`vmax`、欠測なし）。細かい格子の階級を送るとき（全国 1206 × 1222 で 1.5 MB、RGBA なら 6 MB）。RGBA にするのは GPU に置く時刻だけ |
| `GpuFrame.wind` | int16 little-endian、0.01 m/s。u を ny × nx、続けて v |
| `GpuFrame.contours` / `contours_bold` | float32 LE の (経度, 緯度) の並び。線の切れ目は NaN |
| `GpuFrame.labels` | float32 LE の (経度, 緯度, 値) |
| `GpuField.lut` | 256 × RGBA8（`vmin` から `vmax` まで）。A が透明度 |
| `GpuField.base` | 格子点ごとに 1 バイト（1 が陸） |
| `GpuField.coast` | float32 LE の (経度, 緯度)、切れ目は NaN |
| `GpuField.classes` | 値が階級の番号のとき、番号ごとの名前（読み取りに出す。空の名前は出さない） |

格子は北から南の行順。`lon0`・`lat0` は最初の列・行の格子点（セルの中心）。

## 描き方の決まり

- 値は 16 bit を 8 bit 2 つに分けて入れているので、シェーダーは画像の補間（filterQuality）を使わず、
  格子点を 4 つ読んで自分で補間する（上位と下位を別々に補間すると繰り上がりが壊れる）
- 陸海の地色だけは画像の双一次補間で読む（0/1 の境が滑らかになり、海岸がぎざぎざにならない）
- 配色表の透明度で地色と混ぜる（`mix(base, col.rgb, col.a)`）。範囲の外は暗い色
- uniform の並び: uSize(0–1)、uView(2–5)、uGrid(6–9)、uGridN(10–11)、
  uMode(12–15: 投影、経度方向につながるか、地色の有無、最寄りの格子点で塗るか)
- 粒子は Dart で動かし、尾を細い三角形の列にして `drawVertices` で 1 回で描く。尾は画面の位置で
  覚え、表示が変わったときだけ投影し直す（毎コマ投影すると数ミリ秒かかる）
- 海岸線・等値線・札は、表示も時刻も変わらない間は画像（`toImageSync`、画面の画素密度で）にして
  使い回す。拡大・移動の最中（最後の操作から 250 ミリ秒）は直接描く

## 実行環境

自作の Flet 拡張は、Flet の出来合いの実行環境では表示されない。部品入りの実行環境を `flet build`
で作る（AIseed Weather では `tools/build_client.sh` が `build/linux` に作る。Linux の Flet は
起動したフォルダーの `build/linux` を先に使うので、アプリは今までどおり `flet run` で動く）。
Dart かシェーダーを変えたら作り直す。Web 版（`flet build web`）でも描けるが、1 コマの組み立てが
JavaScript で重い。

## Flet 1.0.4 で踏んだ落とし穴

- Flet は既定値のままのプロパティを送らない。Dart 側の既定値は Python 側と同じにする
  （`GpuFrame.index` の既定を Dart で -1 にしていて、0 番の時刻だけ届かなかった）
- `use_effect` の準備の関数から後始末を返しても、描き直すたびに捨てられて呼ばれない。後始末は
  第 3 引数で渡す（使う側のアプリの話。AIseed Weather の `components/task_effect.py`）
- 部品の描画中に例外が出ると、Flet の画面更新が何も記録せずに止まり、画面が固まる

## 地図とグラフへの広げ方（案）

いまは「経緯度の格子を塗る」部品。地図とグラフに広げるには、「投影」を差し替えられる物にして、
その上に層を重ねる形にするのがよいと考える。シェーダーと粒子・線・読み取りの多くはそのまま使える。

### 地図

- ウェブメルカトル図法（シェーダーの投影に 1 つ足す。y → 緯度は `atan(sinh(π(1 − 2y)))`）。
  OpenStreetMap などの背景地図のタイルと重ねられるようになり、気象以外の地図の用途が広がる
- 背景地図のタイル層（出典の表示を必須にする。取得は表示に合わせて Dart 側で）
- ベクトル層: 線・面・点（目印）・文字を、GeoJSON に近い形で受け取る（いまの海岸線と等値線の
  一般化）
- 場の層: いまの格子の塗り（連続・階級）と粒子

### グラフ

- 直交座標（x と y の一次変換）を投影の 1 つとして足す。時刻の軸（UTC と現地時刻）と対数の軸
- 軸・目盛り・格子線・凡例は Dart 側で描く
- 系列: 線（点が多くても 1 回で描く）、点、帯（最小〜最大、アンサンブルの幅）、棒、
  ヒートマップ（いまの格子の塗りがそのまま使える）
- 拡大・移動（x だけ、または両方）、十字線での読み取り

### 共通

- 層の並び: 背景 → 場 → 線と面 → 点 → 文字
- 出典の表示（いまの `attribution`）は、地図でもグラフでも必ず出す
- 時刻の切り替え（`step`）は地図とグラフで同じ仕組みにする
