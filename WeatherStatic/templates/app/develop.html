AIseed Weather 開発マニュアル

初期開発段階 コードは AGPL-3.0-or-later で公開している。このページは開発に参加する （あるいは自分用に改造する）人向けで、使い方は 紹介ページにある。 内容の正本はリポジトリの README.md / AGENTS.md / CLAUDE.md。

環境構築

環境はリポジトリの中に ./.venv として作る。 名前つきのグローバル環境にはしない。

mamba env create --prefix ./.venv -f environment.yml
mamba activate ./.venv
python -m aiseed_weather.main

パッケージは Miniforge / conda-forge（uv ではない）。 cartopy と cfgrib はネイティブ依存（PROJ・GEOS・ecCodes）を持ち、 pip だけで揃えるのが難しいため。 environment.yml が開発環境の正本で、 pyproject.toml は配布メタデータ。

進め方 — スキルを読んでから書く

変更する領域に対応するスキル（.agents/skills/）を 編集の前に読む。これが唯一のハードルール。 Flet の API 取り違えなど、実際に起きたバグはどれも読んでいれば防げた。

順スキル何のガイドか
1aiseed-conventionsプロジェクト全体の決まりと想定利用者
2flet-declarative / flet-component-basicsFlet 0.85+ の書き方（宣言的 UI・hooks）
3user-action-fetchいつデータを取ってよいか（全ビューに関係）
4first-run-setup初回起動と config.toml

7weather-rendering / chart-base-design総観規模の描画と図の層構造
8figure-export / data-flow書き出しとデータの流れ

二つの設計原則

1 データソースは利用者が選ぶ。 ~/.config/aiseed-weather/config.toml を 起動前に編集する。アプリは勝手に選ばないし、設定 UI も出さない。 気象庁だけは機能ごとに有効（公開・無料の API のため設定キー不要）
2 取得は利用者の操作時だけ。 ビューを開く・更新を押す・パラメータを変える。 バックグラウンドポーリングなし、自動更新なし、先読みなし

データ層（それぞれ役割が違う）

層出所役割
予報格子ECMWF Open Data（AWS S3）未来・地図ビュー
気候値・アノマリERA5（AWS）歴史的文脈。差別化の核
日本の現況気象庁レーダー ＋ AMeDAS「いま」のナウキャスト
地点予報Open-Meteo補助ビュー

AMeDAS はこのサイトの裏で動く収集基盤（R2 ミラー）からも読める。 気象庁のサーバーに全員が直接取りに行かなくて済むようにするためのもの。 配信の形は このサイトについてと docs/ を参照。
